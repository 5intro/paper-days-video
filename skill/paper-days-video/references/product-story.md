# Vibecoding 产品模式

## 痛点先成立

先用生活场景讲清谁在什么时刻为什么麻烦、旧办法哪里卡住。展示具体行为链，而非一句“很麻烦”后立刻出现产品。轻幽默来自生活细节。

## 按请求选择演示形态

三种形式都适用，不把制作产品故事自动扩大成开发真实应用：

- **真实应用演示**：使用现成或用户要求开发的应用，采集真实操作。演示状态和按钮要与实际功能一致。
- **可交互原型**：在任务范围内实现需要的界面和状态，用合成但自洽的数据完成片中流程，不声称已经部署或接通不存在的服务。
- **原创 UI 动画 / 概念演示**：直接编写界面画面、动作和状态过渡，不要求真正实现后端或应用。操作逻辑须像可信的产品，不能把预设动画说成已实现的功能。

三者都要有精致独立的产品视觉系统：自己的颜色、排版、间距和组件，不把视频背景纸纹直接铺到应用里。按实际情况在简介准确披露一次，例如“原创界面概念演示”“可交互原型，使用演示数据”或真实应用状态。口播不必反复强调“只是原型”。

按使用情境选择手机或桌面浏览器框：移动任务用手机，复杂表格或管理界面用桌面。真实截图/录屏由当前可用浏览器获得；原创 UI 动画在 `scenes.py` 绘制或从自有设计画面构建。避免展示真实个人资料、账户、token 或通知。

## 镜头设计

概览建立位置 → 放大关键字段/操作 → 状态变化 → 同位置前后比较。停顿留给读数，动画指针与操作声对应画面中的动作。局部放大仍保留空间关系，不用全屏随机卡片切来切去。

采集帧或视频放在 `assets/ui/`；原创动画可以直接用代码绘制。按操作可读性和旁白对齐，不宣传未经实现或测量的性能、节省时间及效果。来源说明记录采用哪种演示形态和数据性质。

示例选题：合租室友的冰箱食材管理。先把“忘记买过、到期才发现”演清，再展示录入、共同查看和优先食用的可信操作流程。可以按任务范围做真实应用、交互原型或原创界面动画。示例只提供叙事方向，不是默认套用的模板文本。
